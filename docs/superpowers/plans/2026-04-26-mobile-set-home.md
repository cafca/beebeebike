# Mobile Set-Home Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add UI in the Flutter app so users can set their home location from Settings, the empty-state Home Sheet CTA, and a long-press on the existing "Go home" button.

**Architecture:** Reuse the existing `homeLocationProvider.save()` + `LocationsApi.setHome()`. Add a `SearchMode` enum to `SearchScreen` so it can either return a picked `Location` (existing route flow) or save it as home and pop. New entry points push the picker, then show a snackbar.

**Tech Stack:** Flutter 3, Riverpod 2 (`AsyncNotifierProvider`), Flutter `gen-l10n` for ARB localization, Material 3 `ScaffoldMessenger`, `HapticFeedback.mediumImpact()`.

**Spec:** [docs/superpowers/specs/2026-04-26-mobile-set-home-design.md](../specs/2026-04-26-mobile-set-home-design.md)

**Provider note:** The spec calls the setter `set()`. The actual method on `HomeLocationController` ([mobile/lib/providers/location_provider.dart:23](../../../mobile/lib/providers/location_provider.dart)) is `save(Location)`. This plan uses `save()` everywhere.
